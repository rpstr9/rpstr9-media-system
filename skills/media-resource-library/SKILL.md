# Reusable Audience Resources

Read [operating boundaries](../../policies/CONSTITUTION.md) and [handoff rules](../../contracts/HANDOFF.md). Use only the current task’s required inputs and references.

## Method
Identify the specific reader need and whether a reusable resource improves it. Decline unnecessary worksheets or participation tasks when the publication's value is experience or appreciation. Inspect the existing inventory and choose reuse, update, create or retire based on current usefulness and maintenance cost.

Build the complete resource with practical start instructions, inputs, expected result, sources, scope and limits. Keep examples outside reusable instructions unless explicitly requested; derive processes and decision criteria from the task. Do not turn a single successful solution into a permanent default.

Test the actual artifact through its intended access route. For a prompt, check complete copyability and task behavior; for a file, check opening, internal links and promised content; for a tool, check the relevant functions. Distinguish structural validation from observed usability and real outcomes.

Return ResourceRecord with artifact/version, purpose, evidence, actual test status, owner, review conditions and dependent content. Keep evergreen checks and correction propagation connected to Publishing. A stale resource may be updated or retired under authorization; do not silently break published dependencies. If execution is unavailable, preserve the resource and state the untested behavior precisely.

## Inputs and outputs

Inputs: Audience or editorial need; Existing resource inventory; Evidence, accessibility and maintenance requirements.

Outputs: ResourceRecord; Versioned resource artifact or update; Links to dependent content.

## Completion and learning

Check the delivered result against the current brief and the relevant evidence, technical and permission criteria above. Retain concise evidence of what worked, failed or remains unavailable in the private run record. Use media-learning for a justified reusable adaptation; current-output repairs do not automatically change the method.

## Use an existing answer before creating infrastructure
Inspect ordinary resources and the reader's remaining work before building a new tool, guide or returning-reader feature. Create only what contributes a worthwhile capability or removes a material obstacle, with a feasible maintenance cost. Keep the core article's value on the page. An optional resource is not a reason to invent an exercise, worksheet or repeated article architecture.
