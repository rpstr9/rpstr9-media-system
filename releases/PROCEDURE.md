# Develop, release and adopt

Keep development and publication evidence outside the public library. Review new methods against their functional contracts and independent cases; report exposed fixtures honestly. Inspect exact source versions and reuse conditions. Existing strategy/identity methods remain external unless separately authorized for vendoring.

Build complete reading bundles from canonical sources with scripts/build_bundles.py. Validate schemas, relative references, hashes and semantic invariants; run the relevant behavioral and runtime tests. Review the explicit public allowlist for private records, secrets, research archives and licensed binaries. Do not publish this project's source handoff.

The owner must authorize the new material's license and public release. Proposed MIT terms are not active until selected. No license is applied to external methods. Resolve all release-critical failures or accurately label the edition experimental and list unsupported routes; never call an incomplete system production-proven.

Create the immutable content commit after finalizing its non-self-referential manifest. Update the channel pointer in a separate commit so metadata need not contain its own hash or commit. Verify anonymous retrieval of the actual entry, full workflow closure and external dependencies independently of authenticated tools.

Adoption is separate: stage the new release privately, back up the prior lock and state, check schema migration and adaptation compatibility, run a representative workflow and switch only under the owner's update policy. Keep incompatible adaptations disabled with reasons. Restore the previous lock/state on failure while preserving new audit evidence. Remote posts require separately authorized correction, not fictional rollback.
